# `night-city.ts` — ночной город и плавающее начало координат

**Роль:** самая сложная часть проекта. Строит изогнутую улицу с домами, вывесками,
мостами и мокрым полотном и **каждый кадр** переносит её в систему координат болида,
переодевая ровно те секции, которые только что появились впереди.
**Строк:** 315. **Экспортирует:** `buildNightCity()`.
**Используется:** `drive.ts`.

## Идея в одном абзаце

Болид не едет по миру — мир едет мимо болида. Есть 13 слотов; каждый слот хранит
набор объектов и «логический» номер секции, которую он сейчас изображает. Когда
машина проходит 24 м, самый дальний слот переезжает вперёд: его дорожные меши
пересчитываются (`defineMesh` заменяет вершины **на месте**), а детали (дома,
вывески) переиспользуются — им меняют позицию, размер, текстуру и видимость. После
переодевания вызывается `snap()`, чтобы рендер не интерполировал скачок.

## Верхние константы и типы

```ts
const HALF = 6, WALK = 2.8, CURB = 0.15, STEP = 4;
type Pose   = ReturnType<typeof routeAt>;
type Piece  = { obj: Mesh; x: number; z: number; yaw: number };  // позиция в мире трассы
type Slot   = { logical: number; used: number; pieces: Piece[] };
type Vertex = [x, y, z, nx, ny, nz, u, v];
const BASES = ['#253341', '#332b3c', '#27303a', '#303143', '#272d40', '#263a41'];
```

| Имя | Значение | Смысл |
|---|---|---|
| `HALF` | 6 | половина полотна (`ROAD_WIDTH / 2`) |
| `WALK` | 2.8 | ширина тротуара |
| `CURB` | 0.15 | высота бордюра |
| `STEP` | 4 м | шаг сэмплирования полотна (7 сэмплов на 24-метровую секцию) |
| `BASES` | 6 цветов | основания пентхаусов |

Вспомогательные:

- `mod(n, m)` — положительный остаток (для отрицательных `logical`).
- `mix(n)` — целочисленный хэш → `uint32`. Детерминированная «случайность»: одна и
  та же секция всегда одинаковая, соседние — разные.

## `ribbon(slot, logical, origin)` — дорожные меши

1. Берутся 7 сэмплов `routeAt(logical·24 + i·4)` — от начала секции до её конца.
2. `strip(out, lo, y0, hi, y1, nx, ny)` строит полосу между двумя боковыми
   границами:
   - вершина `i` = `[p.x − origin.x + offset·p.cos, y, p.z − origin.z + offset·p.sin,
     nx·p.cos, ny, nx·p.sin, u, (i·STEP)/SECTION]`;
   - `u` = 0 или 1 (поперёк), `v` = 0…1 (вдоль секции);
   - на каждый промежуток — 2 треугольника.
3. Полосы:

| Массив | Полосы | Что |
|---|---|---|
| `deck` | −6…+6 при y = 0, нормаль (0,1,0) | асфальт |
| `paving` | −8.8…−6 и +6…+8.8 при y = 0.15 | тротуары |
| `lips` | вертикальные 0…0.15 на кромках ±6, нормали (±1,0,0) | бордюры |

4. `game.world3d.defineMesh('night-deck'+slot, ...)`, `night-paving+slot`,
   `night-curb+slot`. Имена привязаны к **номеру слота**, а не к секции — поэтому
   повторное определение меняет тот же меш, и объект, который его носит, обновляется
   без пересоздания.

Вершины — в абсолютных координатах трассы (минус центр секции). Поэтому угол
поворота уже «запечён» в геометрию; при отрисовке меш поворачивается на
`−heading`, чтобы совпасть с камерой.

## `dress(slot, index, logical)` — переодеть слот

1. `mid = (logical + 0.5)·24`, `origin = routeAt(mid)`.
2. `ribbon(...)` — новые дорожные меши.
3. `slot.logical = logical; slot.used = 0`.
4. Внутренняя `place(name, along, across, y, w, h, d, color, texture?, yaw, mesh, visible)`:
   - `p = along === 0 ? origin : routeAt(mid + along)` — деталь можно сдвинуть вдоль
     дороги;
   - `id = slot.used++` — **индекс детали в слоте**;
   - если объекта с таким индексом ещё нет — `game.spawn({ mesh, unlit: !!texture, rough: 0.85 })`;
   - позиция в мире трассы: `p.x + across·p.cos`, `p.z + across·p.sin`;
   - ориентация: `p.heading + yaw`;
   - затем `o.y`, `o.sx`, `o.sy`, `o.sz`, `o.tint`, `o.visible`, и при текстуре
     `o.frame = game.assets.frame(texture).index`.
5. Внутренняя `surface(name, texture)` вызывает `place` с нулевым смещением и
   принудительно ставит `yaw = 0` (угол уже в вершинах).
6. Стили сторон: `styles = [mix(logical·2) % 6, mix(logical·2+1) % 6]` — по одному
   бренду на сторону. `style` задаёт вывеску, витрину, фасад и `frontage` (0/1/2) —
   вариант планировки.
7. Для каждой стороны (±1) — 15 деталей (см. таблицу в `README.md` §9.3). Номера
   деталей в слоте одинаковы для любой секции — это контракт переиспользования.
8. Мост через дорогу при `logical % 9 === 4`.

### Детерминированная «случайность»

```ts
seed = mix(logical * 53 + side * 293)
height = 10 + (seed % 31)                 // 10…40 м
width  = 7 + ((seed >>> 8) % 6)           // 7…12 м
variation = (seed >>> 12) % 5             // глубина 18…22
signHeight = [6.2, 4.1, 3.3][frontage] + ((seed >>> 14) % 3)
mast visible = seed % 3 === 0
```

Поэтому город «случайный», но не мерцает: переодевание того же `logical` всегда даёт
тот же результат.

## Проёмы между домами

Пространство между двумя фасадами раньше заполнялось только у тротуара, и вглубь
уходила пустая земля. Теперь проём делится на полосы по глубине:

- `parkGap(seed, width)` (`night-props.ts`) — жилой/торговый проём. На глубинах
  −4.3…−16.3 м с шагом 3 м кладутся плиты (`paving-module`) колоннами по 3.2 м;
  в каждой колонне через полосу стоит цветущее дерево, у обеих стен — скамейки
  лицом в проём и плантаторы.
- `serviceGap(seed, width)` — технический (мусорный) проём: ящики, бак и пакеты
  между заборами. Парка здесь нет.
- `stretchLanterns(from, to, height)` для жилых проёмов вешается в два ряда
  (глубина 2.1 и 5.6 м) между внутренними стенами домов, пока хватает их глубины.
- `defineGapFence(mesh, width, height)` строит слэт-забор в метрах под конкретную
  ширину проёма и переиспользуется пулом; забор ставится поперёк проёма
  (yaw = `heading + π/2`) на глубинах 3.1 и 8.2 м. Объекты несут тег `gap-fence`.

Глубина проёма ограничена вторым рядом домов (отступ 23 м), поэтому полосы
заканчиваются на −16.3 м.

## Свет от пропов

Пропы не только светятся текстурой — они настоящие источники света. Лампа объявлена
в данных: у `Placement` в `night-props.ts` есть `lights: PropLight[]`, а `PropLight`
задаёт `color`, `radius`, `intensity`, необязательные `cone` / `pitch` / `dir` (в
градусах) и `offset` — смещение от центра модели в метрах: `+x` вправо, `+y` вверх,
`+z` из «лица» модели. Смещение берётся из запечённой геометрии GLB (модель вписана в
единичный куб, поэтому метры смещения совпадают с реальными).

`modelAt()` создаёт лампы один раз на пуловый кусок и запоминает их место в мире
трассы; кадровый цикл переносит их в систему болида тем же поворотом `−heading`, что
и части. Ключ пула включает цвета и радиусы ламп, поэтому освещённый кусок никогда не
переиспользует неосвещённый.

| Проп | Свет |
|---|---|
| `illuminated-bollard` (столб) | розовый `#ff4fa8`, r 6, i 15 — на диффузоре, 0.7 м над землёй |
| `curb-light` (бордюр) | голубой `#3da9ff`, r 4.5, i 8 |
| `vending-machine` на улице (кофе) | тёплый `#ffd8a6`, r 5, i 10 — перед стеклом |
| `vending-machine` в гараже (продукты) | белый `#eaf4ff`, r 5, i 12 — на витрине |
| `ramen-counter-facade` | жёлтый `#ffc83d`, r 8, i 22 у вывески с чашей + две оранжевые `#ff7a1f`, r 4.5, i 9 у бумажных фонариков |
| `minimart-facade` | тёплый белый `#fff1cf`, r 9, i 30 — за стеклом витрины |
| `flowering-street-tree` (сакура) | голубой прожектор `#5fa8ff`, r 6.5, i 48, конус 32°, `pitch −78°` — снизу вверх в крону |

- `LIGHT_BUDGET` (160) пишется в `game.lights.max` при старте: рендер отправляет только
  ближайшие светильники, и с прежним дефолтом 64 уличные фонари вытесняли неон витрин.
  При бюджете 96 это было заметно (фасады темнели), при 160 — уже нет, кадр держит 60 fps.
- `PROP_LIGHT_GAIN` (1) — общий множитель яркости всех ламп пропов; 0 полностью гасит их
  для A/B-снимка «свет / без света».
- Свет ложится на всё, что освещается: тротуар (`paving` — lit), деревья, пропы, фасады.
  Полотно дороги, бордюр и земля — `unlit`, поэтому фонари их не красят, только сами
  лампы видны в кадре.
- Лампы — объекты ростера с тегом `light` и id вида `night-<model>-lamp`; при выгрузке
  фрагмента они получают `on = 0` и не попадают в кадр.
- Шаг вдоль улицы задают `POST_SPACING` (30 м — столбы и светящиеся бордюры, вразбивку)
  и `DRAIN_SPACING` (18 м — дождевые решётки, они не светят). Раньше оба стояли через
  6 м; фонари на каждом шаге превращали тротуар в сплошную полосу света.

## `buildNightCity()` — сборка и кадровая функция

### Один раз

```ts
game.background.picture('night-sky', 'stretch');
game.render3d.lighting.preset('night');
game.render3d.lighting.set({
    sun: {x: 0.4, y: -1, z: -0.65}, sunColor: '#c6cfee', sunIntensity: 0.96,
    skyColor: '#ccd6f8', groundColor: '#525071', ambient: 0.5, environment: 0.32,
    fogColor: NIGHT_HAZE, fogStart: 150, fogEnd: 320, shadows: true,
});
const pool: Slot[] = Array.from({ length: 13 }, () => ({ logical: NaN, used: 0, pieces: [] }));
```

`logical: NaN` гарантирует, что первый кадр переоденет все слоты.

### Каждый кадр

```ts
const here = routeAt(distance);
const first = Math.floor(distance / SECTION) - 1;

for (let j = 0; j < 13; j++) {
    const logical = first + j;
    const index   = mod(logical, 13);
    const slot    = pool[index];
    const recycle = slot.logical !== logical;
    if (recycle) dress(slot, index, logical);

    for (const p of slot.pieces) {
        const dx = p.x - here.x, dz = p.z - here.z;
        p.obj.x =  dx * here.cos + dz * here.sin;
        p.obj.z = -dx * here.sin + dz * here.cos;
        p.obj.yaw = p.yaw - here.heading;
        if (recycle) p.obj.snap();
    }
}
return pool.length;   // 13 → run.sections
```

- Первая секция начинается за машиной (`−1`), последняя — примерно в 300 м впереди.
- Поворот вектора на `−heading` — перевод из мира трассы в мир болида. Тот же поворот
  применяется к вершинам дороги (через `obj.yaw`), поэтому дорога и дома остаются
  согласованными.
- `snap()` — только что переодетые объекты не должны «проехать» через экран
  интерполяцией.

## Сколько объектов

На слот: 3 дорожных меша + 15 × 2 дома + 2 моста = **35**. На весь город —
**455 объектов**, созданных за первый кадр и больше не создающихся.

## Слабые места

1. **Порядок `place()` — контракт.** Добавлять детали можно только одинаково для всех
   секций (различие — через `visible`). Иначе индексы сдвинутся и детали перепутаются.
2. **`unlit` задаётся при спавне.** Деталь всегда должна получать (или не получать)
   текстуру; иначе при переодевании на неё «не переключится» освещение.
3. **Туман и пул связаны.** Геометрия есть примерно на 312 м вперёд, `fogEnd: 320`.
   Запас 8 м: если сократить пул, станет видна кромка города.
4. **Мост на `% 9`** — при 13 слотах в кадре иногда два моста, иногда ни одного; это
   нормально, но не «каждый девятый на экране».
5. **`ribbon` работает на переодевании**, а не каждый кадр: перестройка вершин 455
   объектов в кадре была бы заметным хичом.

## Где править

| Хочу | Правка |
|---|---|
| шире улицу | `ROAD_WIDTH` в `highway.ts` (HALF считается от него) |
| выше дома | множитель в `height` |
| плотнее город | уменьшить `SECTION` (но тогда больше слотов на те же метры) |
| другой неон | `NEON` и `NAMES` в `night-art.ts` |
| убрать туман | `fogEnd: 0` (но откроется кромка пула) |
| мягче свет | `sunIntensity`, `ambient` |
| больше деталей | новый `place(...)` в конце обеих сторон + правка `slot.used`-контракта |

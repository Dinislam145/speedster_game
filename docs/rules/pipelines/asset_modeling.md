# Правила создания ассетов

Здесь правило создания ассетов для игры. Следуй им в точности.

1. Изучить референс. Если его нет — запросить.
2. ТЗ от человека — если нет, запросить.
3. Потребовать конкретную программу по конкретному скилу для моделирования.
4. Добавить в папку ассетов игры, не расширяя код и не меняя механики. Только модель.

## Для Phaser использовать следующие правила

### 1. Формат сдачи — `.glb`

- Исходник — `.blend` в репозитории; наружу отдаётся **один `.glb`** (бинарный glTF 2.0).
- `.glb` — единственный «авторский» 3D-формат, который читает пак `model-files-3d`.
- `.obj` + `.mtl` допустим только для простых пропов: без анимации, эмиссии и части PBR-полей.
- `.fbx`, `.blend`, `.usd`, `.gltf` + внешний `.bin` — **не грузятся**. Файл должен быть самодостаточным: только собственный BIN-чанк.

### 2. Что загрузчик НЕ читает (проверено в `model-files-3d/dist/index.js`)

Экспорт, который это нарушает, роняет загрузку или молча теряет данные:

| Запрещено | Следствие |
|---|---|
| Draco (`KHR_draco_mesh_compression`) | загрузка падает с ошибкой |
| meshopt (`EXT_meshopt_compression`) | загрузка падает с ошибкой |
| Sparse accessors, morph targets | загрузка падает с ошибкой |
| Текстуры KTX2 / WebP / JPEG | принимается только `image/png` |
| `alphaMode`, `doubleSided` | не читаются: прозрачности нет, backface culling включён |
| `emissiveTexture`, `occlusionTexture` | нет; работает только `emissiveFactor` |
| `TEXCOORD_1` и далее | читается только `TEXCOORD_0` |

Читается: `POSITION`, `NORMAL`, `TEXCOORD_0`, `JOINTS_0`/`WEIGHTS_0` (до 4 костей на вершину), `baseColorFactor`/`baseColorTexture`, `metallicFactor`, `roughnessFactor`, `normalTexture`, `emissiveFactor`.

### 3. Бюджеты (мобильная цель, экран 720×1280)

- **1–3 материала на модель.** Статичная модель мержится в один меш на материал, поэтому каждый лишний материал = лишний draw call.
- Текстуры — **PNG 256–512 px**, встроенные в `.glb`. Детали класть в текстуру/atlas, а не в новые материалы.
- Неон и подсветка — через `emissiveFactor`. Свечение, пламя из двигателя, блики — эффектами движка (билборды/партиклы), а не геометрией и не альфа-текстурами.
- Скины и анимация скелета скинятся на CPU: для гиперказуальной гонки они не нужны. Анимация узлов (колёса, створки) — дёшева, её использовать можно.
- Плоский/жёсткий шейдинг для low-poly киберпанка: меньше вершин, читаемый силуэт на маленьком экране.

### 4. Экспорт

- Модификаторы применены (`export_apply=True`), масштаб объекта 1, +Y вверх.
- Узлы называть по смыслу (`jet`, `wheel_fl`, `hull`) — по ним идёт привязка анимации и поиск частей.
- Имена свойств экспортёра не хардкодить: сначала прочитать валидные идентификаторы, потом вызывать.

```python
props = {p.identifier for p in bpy.ops.export_scene.gltf.get_rna_type().properties}
bpy.ops.export_scene.gltf(
    filepath="//game/assets/<name>.glb",
    export_format='GLB',
    export_apply=True,
    export_draco_mesh_compression_enable=False,
    export_texcoords=True,
    export_normals=True,
)
```

### 5. Куда класть файл

- В `game/assets/*.glb`. **Не в `game/assets.json`**: он принадлежит Phaser AE и перезаписывается командами `upload`/`crew`/`pull`.
- Подключение в коде — без правки механик:

```ts
await game.modelFiles.load('<key>', 'assets/<name>.glb');
const h = game.modelFiles.spawn('<key>', { size: <габарит, м>, y: <центр по Y> });
```

- Модель вписывается в единичный куб **вокруг своего центра**: `size` — самый большой габарит в метрах, `y` у `spawn` — центр модели, а не её низ. Ставить на полотно через `y = size / 2` (или подобранный `HOVER`).

### 6. Гейт проверки перед «готово»

1. `blender-asset-qa` по мешу: z-fighting, неманифолдные рёбра, инвертированные нормали, неприменённый масштаб, UV.
2. Визуальная проверка (`look`, 2–3 ракурса) — силуэт и читаемость на тёмном неоновом фоне.
3. `npm run -s build` — строгий TypeScript и бандл проходят.
4. `npm run -s play -- "shot"` — ассет виден в игре на своём месте, без провалов и «плавающих» частей.
5. Отчитаться цифрами: треугольники, материалы, габариты (`ob.dimensions`), путь файла.
